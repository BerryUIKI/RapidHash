# Governance

RapidHash currently uses a maintainer-led governance model.

## Roles

- **Maintainers** set project direction, merge pull requests, manage releases,
  handle security reports, and enforce community policies.
- **Reviewers** provide domain review but do not merge without maintainer rights.
- **Contributors** submit issues, documentation, designs, tests, and code.

## Decision Making

Routine decisions are made through pull-request review. Changes that affect the
public architecture, file formats, security boundaries, licensing, compatibility,
or governance require an Architecture Decision Record (ADR).

Maintainers seek consensus. When consensus cannot be reached, the repository
owner makes the final decision and records the reasoning in the issue, pull
request, or ADR.

## Maintainer Changes

Maintainers may invite contributors who demonstrate sustained, constructive,
and technically sound participation. Maintainer access may be removed for
inactivity, security reasons, or violations of project policy. Material changes
to maintainership should be documented publicly unless privacy or security
requires otherwise.

## Project Assets

Repository administration, package namespaces, signing identities, domains, and
release credentials must be controlled by maintainers and protected with
multi-factor authentication where available.
